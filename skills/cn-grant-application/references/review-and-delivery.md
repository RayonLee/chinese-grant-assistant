# 复核与交付

## 按任务大小复核

对完整申报稿或实质重写，完成以下检查。有独立审阅能力时，可分别检查论证与引用；给审阅者原始材料和现稿，不用“新版更好”预设结论。仅修改一句用语时不自动启动全套研究和文献检索。

1. **符合指南**：类别、主方向、资格、人数、周期、经费、成果、匿名要求、模板和字数均来自本次文件。冲突或关键缺项明确说明。
2. **论证完整**：课程/研究问题有依据；具体做法能回应问题；方法和现有条件相符；预期成果能验收。不将计划写成已完成事实。
3. **各处一致**：名称、对象、数量、时间和分工前后一致；总体计划与课程/实验/调研安排一致。没有真实分工的字段保持空白。
4. **文献可靠**：正文与文后条目一一对应，文献支持相邻论断；核验范围据实记录。未阅读全文不写“全文核验通过”。
5. **语言自然**：把抽象术语还原为能看懂的活动，同时保留真实研究条件。已被用户改顺的句子不为显示修改量而重写。
6. **模板与文件正确**：最终写入的内容与通过复核的稿件一致。保留原有签章、复选框、表格及空白项；需要时按文档工具流程逐页检查，不把生成成功当作排版检查成功。

## 字数检查工具

`scripts/check_sections.py`只读取整理后的栏目文本，不解析Word，也不判断引用真伪、内容完整性或格式。适合重复核对申报栏目上限；将正文、引文和栏目内表格文字完整放入texts，防止漏计。

输入为UTF-8 JSON，例如：

```json
{
  "sections": [
    {"name": "项目简介", "limit": 500, "texts": ["正文与作者年份引文"]},
    {"name": "工作计划", "limit": 500, "texts": ["计划说明", "表头", "各表格单元格文字"]}
  ]
}
```

这里的500仅为示例，从本次模板读取实际limit；不设上限的栏目可省略limit。调用：

```text
python3 <本技能目录>/scripts/check_sections.py <栏目文本.json>
```

工具按Unicode非空白字符计数，包含标点、引文、表格文字，每个英文字母也单独计数。这是保守自检口径，不等于Word或资助方的“字数”。退出码0表示未发现超限，1表示超限，2表示输入无效。若官方另有口径，按官方检查；不得为通过工具而遗漏引文或表格。

## 修订对比

实质修改已有稿时，说明具体变化、理由和取舍。例如：总表与课程表日期统一、成果与任务关系更明确、把背景中的方法移到研究内容。区分原稿已有的优点与本轮新增内容；不把原有设计算作技能新贡献。

新增加的研究任务、评价方式或工作量需要标为拟议安排。对比记录建议写“原文/原安排—改后—原因—是否建议采用”，选最重要几处即可。只有用户要求整份对照或修订痕迹时才制作相应版本。

不得根据技能热度给申报质量背书。多个技能共同试用时，不能声称精确识别单个技能的贡献或提高立项率。

## 默认交付

按用户本轮要求确定，不固定输出一套材料：

- 完整新申报：申报书及必要的待补事项。用户允许自主执行时直接写完可完成部分。
- 完整修改：修订稿与简短改动说明，默认另存，保留基准稿。
- 仅润色、方向判断、列参考文献：只交付指定结果，不重写其他栏目。
- 仅prompt/计划：提供可复用文本，用户要求本地txt则保存txt，在明确授权前不执行后续申报写作。

最终答复给出文件位置、主要改进和实质未完成事项。不要把中间脚本、调试日志和冗长过程报告当成用户成果。只有做过实际渲染/查看才说“已检查排版”，只有核对过所述范围才说“已核查文献”。
